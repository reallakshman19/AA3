## First wrong boundary

The physical probe already required `currentAuthority === true` and `computationalState === 'CURRENT_RESULT'`, but the real store did not derive those values from current parent identities. A post-`run()` success flag would therefore be stale-authority-prone: after a governing source/mesh/solver edit, an old accepted execution could remain visually/currentness-qualified even though its immutable parents no longer matched the current model.

The owning repair boundary is the workbench lifecycle/currentness projection, not the probe, solver, acceptance tolerance, or UI.

## Changed production

### `src/workspace/lafea-workbench-currentness.js`

Added a pure `lafea-workbench-currentness/v1` projection with the frozen computational vocabulary:

`EDITED | READY | MESHED | RUNNING | CURRENT_RESULT | STALE_RESULT | REJECTED`

and orthogonal qualification vocabulary:

`NOT_EVALUATED | FAIL | PASS`.

`CURRENT_RESULT` requires exact current lineage across source binding, canonical model, analysis geometry, mesh receipt/custody, preflight/solver configuration, execution receipt, completed run-transaction receipt and recovery receipt. Parent mismatch produces fail-closed blocking reasons.

`currentAuthority` is deliberately a **currentness** signal only: it is true exactly for `CURRENT_RESULT`, independent of qualification. The physical probe then applies its separate accepted-execution gate. This preserves the contract's qualification/currentness orthogonality instead of collapsing `CURRENT_RESULT/FAIL` or `CURRENT_RESULT/NOT_EVALUATED` into stale execution.

`REJECTED` is distinct from `STALE_RESULT`: it requires an explicit failed execution or a superseded run-transaction receipt carrying a rejection reason. An unrelated orchestration/UI failure does not reclassify retained historical evidence as rejected.

### `src/workspace/lafea-workbench-run-transaction-state.js`

Extracted `deriveLafeaSolverConfigHash(preflight)` and made `sourceHash` an explicit input to `lafea-solver-configuration-binding/v1`, matching the declared Gate-0 direct parent `solverConfigHash <- sourceRevisionHash`.

No solver settings, tolerances, algorithm, formulation, or numerical output are changed.

### `src/workspace/lafea-workbench-domain-first-execution-state.js`

Retains the latest immutable completed or superseded run-transaction receipt when current execution is cleared/replaced. Historical PASS/rejection custody therefore survives invalidation without granting current authority.

### `src/workspace/lafea-workbench-domain-first-run-actions.js`

On a rejected transaction, retains the immutable superseded transaction receipt before clearing current execution state. No success flag is set.

### `src/workspace/lafea-workbench-orchestrator-store.js`

Publishes the pure currentness projection at the canonical stage-state publication boundary. Display state remains downstream and cannot become an authority parent.
