## Concrete defect

Issue #1559 requires each screen to be inspected for icon meaning/consistency and defines a confusing icon/control as an acceptance failure when its accessible meaning is unclear or inconsistent.

The merged walkthrough harness currently retains, per checkpoint:

- one viewport PNG;
- one full-page context PNG;
- scroll/viewport coordinates in the manifest.

The human-review record permits acceptance from captured artifacts **or** live observation. PNGs can prove visible labels and layout, but they cannot prove a non-visible accessible name supplied through the accessibility tree, nor can they establish whether an icon-only control has a stable accessible name across checkpoints. Therefore an artifact-only reviewer could not validly close the icon/control accessibility part of #1559 even after a passing browser run.

This is an acceptance-evidence defect, not a WRC product-mechanics defect.

## Source basis

- `docs/emp1/EMP1_WRC_UI_WALKTHROUGH.md` says a checkpoint fails when an icon/control lacks clear accessible meaning or changes meaning between screens.
- The same rubric says icon PASS requires a self-evident labeled control or an accessible name/tooltip consistent with the same icon elsewhere.
- `e2e/emp1-professional-walkthrough-evidence.spec.js` currently attaches only viewport/full-page PNG evidence plus the manifest.
- `package.json` pins `@playwright/test` and `playwright` at `^1.59.1`, which supports locator ARIA snapshots.

## Minimal authorized patch

Evidence layer only:

1. At each of the existing 12 checkpoints, attach an ARIA snapshot for the WRC workbench in addition to the viewport and full-page PNGs.
2. Extend the manifest attachment policy to require 12 ARIA snapshots.
3. Update the human walkthrough document so artifact-only acceptance of icon/control meaning requires either:
   - a visible self-evident label in the PNG, or
   - a stable accessible name visible in the retained ARIA snapshot.
4. If meaning depends only on a hover-only visual tooltip not represented in the accessibility evidence, require live/recorded observation for that control; otherwise the relevant checkpoint remains PARTIAL.
