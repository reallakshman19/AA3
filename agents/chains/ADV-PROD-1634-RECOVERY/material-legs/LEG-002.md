## Diagnosis

The last executable production build measured the eager main JavaScript chunk at approximately 1,834,272 B against the unchanged 1,179,648 B hard ceiling. Its Rollup diagnostics reported `src/workspace/emp1-workbench-product-run.js` as both statically and dynamically imported.

Merged-main source inspection showed why: `lafea-workbench-controller.js` synchronously imports `currentEmp1WorkbenchRouteAuthority()` from that module for UI/readiness projection, while `runEmp1Product()` separately dynamically imports `executeEmp1WorkbenchProduct()`. The product-run module itself also eagerly imported the full retained A/B/C transaction stack and LAFEA stage executor, so the intended transaction dynamic boundary could not isolate those dependencies.

## Material changes

### `src/workspace/emp1-workbench-product-run.js`

- remains the single owner of `currentEmp1WorkbenchRouteAuthority()`;
- retains the existing route-authority snapshot schema, decision logic, suspension reasons, semantic payload and semantic hash behavior;
- retains the public async `executeEmp1WorkbenchProduct(options)` export;
- replaces eager transaction dependencies with a dynamic load of `./emp1-workbench-product-execution.js`;
- injects the existing `currentEmp1WorkbenchRouteAuthority` resolver and retained-C schema into the transaction implementation.

The authority-function source is frozen by the new guard against the pre-LEG merged-main SHA-256:

`74f6ebdacfff23d14dd12262b23535f49dc901538c4cbfa013cc458666c3d197`

### `src/workspace/emp1-workbench-product-execution.js`

New lazy implementation module containing the moved transaction implementation and execution-only helpers. It imports the existing qualified EMP.1 execution barrel and LAFEA stage executor. It does **not** import the eager product-run owner; live route authority is resolved through the injected owner callback at the same point in the transaction sequence as before.

### `scripts/bundle-lazy-emp1-product-run-check.mjs`

New structural guard for:

- unchanged authority-function source hash;
- public async lazy delegation;
- absence of full EMP.1 execution-barrel and LAFEA stage imports from the eager owner;
- presence of those execution dependencies in the lazy module;
- no static/dynamic import back from the lazy implementation to its eager owner;
- live route authority resolution through the injected existing owner.

## Engineering limitation

The synchronous route-authority owner still imports the authorized WRC route module, and that route module itself imports qualified WRC execution dependencies. Therefore this source split is a valid lazy-boundary correction but its actual byte saving cannot be inferred from source movement alone. A measured production build must determine whether this closes enough of the ~655 KB historical gap or whether a subsequent packaging-only seam is required.

## Acceptance / rollback rule

LEG-002 remains `IMPLEMENTED_NOT_ACCEPTED` until a faithful exact-head production build demonstrates the generated chunk graph and byte sizes and a served production browser boot is clean. If the build fails to create a distinct lazy execution boundary, creates a generated cycle/TDZ, changes EMP.1 qualification output, or provides insufficient size reduction, revert/re-isolate this leg before broadening scope. Do not raise the ceiling.
