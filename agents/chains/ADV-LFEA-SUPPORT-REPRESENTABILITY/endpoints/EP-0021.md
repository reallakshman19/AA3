## Why this endpoint exists

A re-read of live issue #1551 found a remaining definition-of-done custody gap rather than a mechanics gap. Item 2 requires an exercise model per feature **with the refusal case kept as its own model**. Rigid skew already had `UnsupportedSkewSupport.xml`, but rigid CNODE and incomplete HANGER were retained together in `UnsupportedSupports.xml`.

That combined fixture proved both refusals existed, but it did not satisfy the stronger per-feature custody requirement: one terminal finding could mask or contaminate the other and the repository did not retain an independent negative model for each of those two legs.

## Unified refusal-fixture gate

New `scripts/lfea-support-refusal-fixture-check.mjs` exercises all three dedicated negative models under both:

- `STRICT_INPUTXML_LINEAR_STATIC_V1`;
- `DISCLOSED_GENERIC_ANALYZER_APPROXIMATION_V1`.

For each fixture it requires:

1. pre-flight status remains `BLOCK`;
2. the feature's exact named terminal refusal is present;
3. neither of the other two issue #1551 terminal refusal codes is present.

This establishes that each negative model fails because of the feature it owns, not because another terminal support feature is present.

The check is imported by `scripts/lfea-spring-draft-model-check.mjs`, so the dedicated refusal custody is part of the existing aggregate rather than orphan coverage.
