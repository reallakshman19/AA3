## Material change

EP-0018 authored a mixed fixed + grounded directional spring exercise but intentionally deferred the public reaction aggregation/decomposition decision until more evidence existed.

A production-source trace now resolves the risk without changing solver mechanics:

- `linear-fea-solver/solve.js` forms constrained residual reaction entries and grounded directional-spring component entries separately;
- a directional spring deliberately has no scalar occupied DOF, so the model contract permits a valid rigid UX restraint and a skew spring at the same node;
- therefore that valid mixed model can produce more than one raw support contribution with the same `nodeId:dof`;
- `generic-inputxml-solve-case.js::nodalResult()` previously used first-match lookup and could omit one contribution;
- the engineer-facing Output surface does not use that helper: `lfea-pipeline-results-panel.js` calls `nodeResultRows(active.reactions, ...)` from `lfea-pipeline-results-view-model.js`;
- `nodeResultRows()` previously assigned `values[row.dof] = ...`, so a later same-node/same-DOF contribution overwrote the earlier one. This affected the visible Support loads table, resultants, summary maxima, sorting and CSV export.

## Landed fix

The narrow presentation owners now aggregate contributions while retaining raw solver evidence unchanged:

1. `generic-inputxml-solve-case.js::nodalResult()` sums every matching reaction contribution for each node/DOF. Displacement lookup remains the existing unique first-match projection.
2. `lfea-pipeline-results-view-model.js::nodeResultRows()` accumulates repeated same-node/same-DOF values instead of overwriting them. The same view-model drives visible support-load rows, force/moment resultants, summary maxima, sort and CSV.
3. `lfea-mixed-fixed-skew-reaction-check.mjs` now requires both the core nodal projection and the visible Output projection to equal the sum of all underlying mixed-node UX support contributions.
4. `lfea-results-reaction-aggregation-check.mjs` provides a pure presentation guard proving duplicate support contributions sum and ordinary unique displacement projection remains unchanged. Its deliberate-break mode changes one contribution so the expected aggregate must turn red.
5. The pure presentation guard is imported by `lfea-spring-draft-model-check.mjs`; it is not orphan coverage.

No stiffness matrix, load vector, factorization, equilibrium criterion, reaction sign convention, solver evidence row, CAESAR reference, tolerance, BM4 parity rule or DRAFT status changed.
