## Source diagnosis at integrated merge commit

`LafeaWorkbenchView` wires the complete-sample button to `onLoadEmp1QualificationSample`, which dispatches `LafeaWorkbenchController.loadEmp1QualificationSample()`.

The controller method currently:

1. creates `createEmp1WorkbenchQualificationSample()`;
2. imports `sample.aDocument` into LAFEA.1;
3. imports `sample.bDocument` into LAFEA.2;
4. applies `sample.runInput`;
5. selects LAFEA.2;
6. immediately calls `runEmp1Product()`.

It does not execute/retain LAFEA.1 in the store before the governed product run.

The sample factory itself executes LAFEA.1 only internally to construct admissible B source evidence, then deliberately returns only `aDocument`, `bDocument`, and `runInput`. It does not return/inject the A execution. This is authority-correct fixture behavior, but it means the controller must establish current A execution through the normal store/controller execution path.

The failure is also pre-existing documented debt in `EMP_TAB_UI_RECOMMENDATIONS.md` §4.1: from a clean tab the complete sample loads A/B then attempts C without running A first, producing `EMP1_A_CURRENT_QUALIFIED_RESULT_REQUIRED`; the recommendation explicitly says to fix the sequencing by running/accepting A before C.
