## Newly isolated state-leak defect

`LfeaPipelineCaseSelectionPanelController` retains `selectionExplicit` and `selected` for the lifetime of the mounted controller. The controller is reused while `options.getPreFlight()` can point to a newly loaded source model.

Case IDs are not source-unique (`IXP-W`, `IXP-WP`, etc.). Therefore:

1. model A can have an explicit, applied non-H comparison `IXP-W`;
2. a new hanger model B can be loaded into the same mounted controller;
3. model B's native intake also starts with applied `IXP-W`;
4. stale `selectionExplicit=true` plus stale selected `IXP-W` can make Run custody report ready on model B even though no Load-case decision has been made for model B.

This is presentation/custody state leakage, not a numerical mechanics issue.

## Safe next batch

Reset selection state only when the underlying sealed source identity changes.

Use a source-stable identity such as `preFlight.sourceSummary.sourceSemanticHash` (or the equivalent sealed InputXML source semantic hash). Do **not** key the reset to `intakeSemanticHash`, because requested case IDs are part of intake identity and legitimately change when Apply selection regenerates the same source.

Required behavior:

- same source + Apply selection: explicit selection remains authoritative;
- same source + preflight regeneration/authorization: no reset;
- new source semantic identity: clear `selectionExplicit`, clear selected IDs, return to governed default for the new model;
- no-H legacy model switch remains behaviorally unchanged;
- no source identity available: fail conservatively without inventing identity.

## Validation design

Extend `scripts/lfea-hanger-case-selection-check.mjs` to reconstruct two source identities using the same case IDs:

- source A: explicit/applied non-H comparison is ready;
- switch to source B with hanger cases and native applied `W`: stale explicit state must be discarded and Run must block pending new Load-case application;
- regenerate source B after applying H-bearing cases: explicit/default state must not be spuriously reset by requested-case identity drift;
- deliberate-break disabling source-identity reset must make the check fail.
