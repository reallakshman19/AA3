## Q1 — Production trace

The production path to preserve is:

1. `buildLfeaErrorCheckPresentation` groups governed findings for the common Error Check view without owning disposition authority.
2. `mountLfeaCommonErrorCheckPanel` renders that presentation inside the LFEA pipeline shell.
3. The active source controller, including the ACCDB input panel used by BM4_L, owns the reviewer/reason authorization callback and prepares the full limitation/finding set.
4. `authorizeLinearPipingInputXmlPreFlight` and `authorizeInputXmlLinearSolve` enforce semantic identity, exact conditional-set equality and the prohibition on authorizing BLOCK state.

The UI therefore delegates authorization to the existing controller; it never writes an authorization object directly into analysis state.

## Q3 — Invariants and edge cases

- PASS, ADVISORY, CONDITIONAL and BLOCK retain their governed dispositions.
- ADVISORY review is non-gating and cannot be confused with conditional authorization.
- Every current conditional limitation group must be acknowledged before submission; this is a UI completeness gate, not a replacement for core exact-set validation.
- The source controller remains responsible for the complete limitation and finding payload; duplicate, missing or stale identities must still fail in core authorization.
- BLOCK can never be approved, even if conditional acknowledgements are complete.
- A source, profile, B31/B31J basis, geometry or other semantic change invalidates the sealed authorization through the existing hash/state path; local checkbox state must also reset when the active pre-flight identity changes.
- Empty and already-authorized states must not expose a misleading authorization button.
