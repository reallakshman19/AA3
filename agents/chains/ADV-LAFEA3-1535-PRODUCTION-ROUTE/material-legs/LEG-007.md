## Material changes

This leg repairs source-confirmed engineer-flow defects only. It does not change FEA formulation, assembly, solver, mesher, physical-probe mathematics, convergence acceptance mathematics, benchmark values/tolerances, source/oracle authority, release policy, LAFEA.4/.5 numerics, or workflow YAML.

1. `LafeaWorkbenchController` now constructs the public `createLafeaWorkbenchStore()` rather than the raw orchestrator. The visible product therefore receives the existing convergence-aware wrapper and result-publication custody.
2. The controller exposes the existing `runContinuumConvergenceStudy()` transaction to the workbench view.
3. Guided workflow now contains explicit `RUN -> CONVERGENCE -> RESULTS_EVIDENCE` ordering. A qualified solve remains a completed Run step while downstream Results can remain convergence-gated.
4. A LAFEA.3 convergence setup/status surface exposes only displacement point probes and explicit coarse mesh size; the governed 2:1 ladder is generated as h, h/2, h/4. Acceptance tolerances are not editable in the UI.
5. The next-action banner no longer says the result is ready merely because execution is QUALIFIED. It directs the engineer to Convergence until CURRENT_PASS custody exists, and only then allows a Results-ready presentation.
6. Workflow presentation includes a separate Convergence area. Outside LAFEA.3, the canonical `WORKFLOW_STEP_NOT_APPLICABLE` disposition is rendered as `NOT_APPLICABLE`, not falsely as COMPLETE.
7. The former triangular play glyph for Solve was replaced by a calculation-style symbol. The UI already renders visible text labels and ARIA labels; this change removes the remaining misleading execution metaphor.
8. Convergence/source-staleness/result-gating reason codes now have engineer-facing presentation labels rather than falling through to raw-code-derived text.
9. Added `scripts/lafea.3-visible-convergence-flow-check.mjs` as a focused source/anti-drift guard. It is retained but has not executed in a faithful repository checkout.
