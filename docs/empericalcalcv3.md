# Empirical Calc V3 — Physics-Dominant Piping Restraint ROM

## 1. Purpose

Empirical Calc V3 is the target architecture for a fast piping restraint-load calculation method that remains primarily mechanics-derived rather than curve-fit-driven.

The method is intended to sit between simple screening formulae and a full finite-element/frame analysis. It should provide rapid support-reaction and displacement estimates from canonical piping geometry, material/section authority, operating temperature, restraint data, and component flexibility rules while retaining a defensible engineering evidence chain.

The design objective is:

```text
physics-derived structural response
+ bounded code/component corrections
+ explicit support/contact laws
= rapid engineering ROM
```

The target philosophy is approximately **95% explicit mechanics / 5% bounded empirical or code correlation**. The percentage is an architectural objective, not a numerical calibration rule. The governing requirement is that every non-first-principles contribution is identifiable, source-bounded, auditable, and cannot silently compensate for missing physics.

This method is deliberately **not a finite-element solver**. It does not use a globally assembled nodal stiffness matrix as its primary solution route.

---

## 2. Position in the analysis hierarchy

Empirical Calc V3 is a reduced-order analytical piping mechanics method.

### 2.1 V3 route

```text
canonical piping geometry
        ↓
component mechanics
        ↓
unit-load internal action fields
        ↓
virtual-work flexibility matrix F
        ↓
free/reference movements
        ↓
restraint/support compatibility
        ↓
support reactions
        ↓
engineering evidence / qualification
```

### 2.2 Detailed frame/FEA route

```text
nodes + elements + DOFs
        ↓
element stiffness matrices
        ↓
global K
        ↓
loads / initial strain
        ↓
K u = f
        ↓
element action recovery
```

The two routes share continuum and structural mechanics concepts, but their computational authority must remain separate.

Empirical Calc V3 shall therefore satisfy the architectural rule:

> The empirical piping ROM derives response from analytical flexibility/influence coefficients and compatibility. It shall not silently become a general frame finite-element solver by introducing global nodal stiffness assembly as its primary solution method.

A detailed frame or FEA solver may later act as an independent qualification or escalation authority, but not as hidden runtime mechanics inside V3.

---

## 3. Engineering objectives

V3 should ultimately answer the following classes of questions quickly and traceably:

1. What support reactions arise from thermal expansion?
2. What reactions arise from imposed support/ground movement?
3. What reactions arise from weight, point loads, pressure-derived loads, or other governed load cases?
4. Which supports lift off or close a gap?
5. Which support directions become active or inactive?
6. How much load redistribution occurs because of route flexibility?
7. How much do elbows, branches, reducers, valves, and other components alter the flexibility relative to straight pipe?
8. What is the sensitivity to support stiffness, component flexibility, pressure correction, temperature, and geometry?
9. Where is the ROM outside its qualified domain and a detailed piping/frame/FEA analysis required?

The method must fail closed when any required physical authority is missing or ambiguous.

## 4. Core mechanical formulation

### 4.1 Unit-load flexibility

For generalized coordinate cases `i` and `j`, the base prismatic contribution is

```text
f_ij = Σ_m ∫_m [
    N_i N_j / (E A)
  + M_y,i M_y,j / (E I_y)
  + M_z,i M_z,j / (E I_z)
  + T_i T_j / (G J)
] ds
```

where:

- `N` = axial force,
- `M_y`, `M_z` = bending moments,
- `T` = torsion,
- `E` = Young's modulus,
- `G` = shear modulus,
- `A` = area,
- `I_y`, `I_z` = second moments of area,
- `J` = torsion constant.

The internal actions are generated by static cut equilibrium under explicit one-newton generalized unit loads. Caller-supplied internal-force diagrams are not accepted as authority.

The resulting matrix `F` has units of `m/N` for translational generalized coordinates.

### 4.2 Reciprocity

For a linear conservative domain,

```text
f_ij = f_ji
```

is a mandatory mechanical check, not merely a numerical convenience.

### 4.3 Support flexibility

For each active coordinate:

```text
S_i = 0        rigid bilateral support
S_i = 1 / k_i  finite linear support stiffness
```

where `k_i > 0` is an explicitly governed support stiffness.

No hidden generic support stiffness is permitted.

### 4.4 Compatibility solution

The governing force-method relation is

```text
(F + S) R = δ_target - δ_reference
```

where:

- `F` = pipe/system flexibility matrix,
- `S` = diagonal support-flexibility matrix,
- `R` = reaction on the pipe, positive along the coordinate direction,
- `δ_reference` = displacement of the released/reference structure under the governed load,
- `δ_target` = imposed support/ground displacement.

Recovery is

```text
δ_pipe = δ_reference + F R
δ_support = S R
δ_pipe + δ_support = δ_target
```

For a spring:

```text
R = k (δ_target - δ_pipe)
```

The compatibility, matrix conditioning, positive-definiteness where applicable, reciprocity, and energy closure are retained as evidence.

## 5. Thermal-load philosophy

Thermal expansion is treated as **initial strain / eigenstrain**, not as an externally guessed thermal force.

For a uniform-temperature straight component:

```text
ε_th = α ΔT
ΔL = ε_th L
Δu = ε_th (r_J - r_I)
```

where

```text
ΔT = T_analysis - T_reference
```

For a rooted route, free expansion is accumulated kinematically to obtain the reference displacement at each restraint coordinate.

The reactions then emerge from compatibility:

```text
(F + S) R = δ_support - δ_thermal_reference
```

For a fully restrained straight axial bar, the familiar result

```text
R = -E A α ΔT
```

must emerge from the compatibility solution. It is not injected as the primary thermal load.

### 5.1 Thermal coefficient authority

Current qualified scalar CTE bases are intentionally narrow:

- constant over the relevant temperature range;
- approved mean coefficient between governed reference and analysis temperatures.

The current source-bound bridge uses the repository's approved mean-from-baseline CTE only when its reference-temperature basis is valid.

Future support for general temperature ranges must use one of:

```text
ε_th = ∫[T_ref→T_op] α(T) dT
```

or a source-authoritative total expansion difference.

A generic constant-alpha approximation must not be silently used outside its approved range.

### 5.2 Thermal gradients

Through-wall or through-section thermal gradients are a separate mechanics problem because they generate curvature/bending in addition to uniform axial expansion.

They are not included in the current V3 thermal domain.

## 6. Continuous elbow mechanics

A principal V3 upgrade over scalar directional compliance and segmented-bend approximations is the continuous circular-elbow component.

For a circular arc:

```text
r(θ) = C + R e_r(θ)
```

with tangent

```text
t(θ) = dr/ds
```

For a unit generalized force applied downstream:

```text
F_int(θ) = -F_unit
M_int(θ) = -(r_load - r(θ)) × F_unit
```

The internal actions are resolved on the moving elbow basis:

```text
N        = F_int · t
M_ip     = M_int · n_plane
M_op     = M_int · e_r
T        = M_int · t
```

The component flexibility contribution is

```text
f_ij = ∫ [
    N_i N_j / (E A)
  + k_in  M_ip,i M_ip,j / (E I)
  + k_out M_op,i M_op,j / (E I)
  + k_t   T_i T_j / (G J)
] ds
```

For the current circular-pipe domain, the public route requires an axisymmetric section so that no ungoverned principal-axis orientation is introduced.

### 6.1 B31J flexibility authority

ASME B31J bend flexibility is treated as a **component-local code correction** to elastic energy.

It does not replace:

- arc geometry,
- force equilibrium,
- moment transport,
- section properties,
- thermal strain,
- route topology,
- restraint compatibility.

Only the governed flexibility factors are used by the ROM component:

```text
k_in-plane
k_out-of-plane
k_torsional
```

Stress intensification factors are not used as stiffness multipliers.

This distinction is mandatory:

```text
SIF ≠ flexibility factor
```

### 6.2 Pressure-corrected bend flexibility

Where a qualified B31J result includes pressure correction of bend flexibility, that corrected `k` may be used as the component flexibility authority.

That does not automatically add:

- pressure thrust,
- translational Bourdon effect,
- rotational Bourdon effect,
- any other pressure-load mechanism.

Each of those mechanisms requires separate explicit formulation and qualification.

### 6.3 Elbow thermal expansion

For uniform isotropic thermal strain:

```text
Δu_end = ∫ ε_th t ds
       = ε_th (r_J - r_I)
```

while physical arc-length growth is

```text
ΔL_arc = ε_th R θ
```

The distinction allows the ROM to preserve both kinematic end movement and physical component expansion evidence.

## 7. Source and authority architecture

V3 must never create a second, parallel engineering truth model.

The intended authority chain is:

```text
canonical imported / authored model
        ↓
source identity + semantic hashes
        ↓
component classification and exact topology
        ↓
material / section / process-state authority
        ↓
component mechanics authority
        ↓
load/reference displacement authority
        ↓
ROM solve
        ↓
immutable evidence
```

### 7.1 Required authoritative inputs

Depending on the analysis case, V3 requires explicit custody for:

- component identity;
- connectivity;
- coordinates;
- exact component kind;
- pipe OD and wall thickness;
- bend centreline radius;
- bend included angle;
- bend plane/orientation;
- E and G;
- A, Iy, Iz, J;
- reference and operating temperatures;
- thermal-expansion coefficient basis;
- pressure where it affects a qualified component rule;
- support identity;
- support location;
- support direction;
- support state/type;
- support stiffness;
- support/ground displacement;
- load-case identity.

If required data are missing, ambiguous, inferred only for rendering, or stale relative to source hashes, the calculation must block.

### 7.2 No renderer authority

Display geometry is not automatically mechanics geometry.

For example, a viewport may legitimately render a missing-radius elbow using a visual long-radius assumption such as `1.5D`. V3 must not consume that fallback as structural authority.

The rule is:

> Visual fallback is presentation evidence only. Structural mechanics require explicit or separately qualified geometric authority.

## 9. What V3 must not become

V3 must not degrade into any of the following:

### 9.1 Hidden calibration engine

Do not introduce generic response multipliers to force agreement with one benchmark.

### 9.2 Tolerance-driven acceptance

Do not widen an engineering or benchmark tolerance because one route fails.

### 9.3 Disguised FEA

Do not migrate the core architecture into arbitrary nodal FE discretization and global stiffness assembly while continuing to call it an empirical ROM.

### 9.4 Silent-default calculator

Do not assume:

- ambient/reference temperature;
- CTE;
- pipe schedule;
- bend radius;
- support stiffness;
- support movement;
- missing component weight;
- fluid density;
- valve weight;
- pressure area;
- material properties.

### 9.5 SIF-as-stiffness model

SIFs govern stress intensification and code-stress recovery. They are not interchangeable with flexibility factors.

## 10. Qualification philosophy

Three separate questions must be kept distinct.

### 10.1 Physics purity

How much of the response comes from explicit mechanics versus empirical or code correlation?

### 10.2 Physical completeness

Are all material mechanisms relevant to the target engineering problem represented?

A method can be nearly 100% first-principles within its equations but still be physically incomplete if, for example, it omits pressure thrust, friction, or elbow flexibility.

### 10.3 Qualification maturity

How extensively has the implemented domain been independently validated?

These three axes must not be collapsed into a single percentage.

---

## 11. Independent validation hierarchy

Expected values must not be generated by the V3 implementation itself.

Preferred qualification order is:

1. exact analytical mechanics;
2. closed-form structural benchmarks;
3. standards/code formula reproduction;
4. published benchmark examples;
5. independent commercial piping-stress solver;
6. independently converged detailed FEA;
7. field or test measurements where suitable.

Every benchmark should freeze before observation:

- geometry;
- properties;
- loading;
- boundary conditions;
- expected quantities;
- physical probe locations;
- comparison rules;
- acceptance thresholds.

Production outputs must not be used to choose their own targets or tolerances.

---

## 12. Accuracy policy

The long-term target should be judged by a benchmark portfolio, not by isolated hand-picked cases.

A proposed maturity target for qualified route families is:

```text
median reaction error:       5–8% or better
P95 reaction error:          ≤15%
outer maximum error:         ≤20%
contact-state/sign errors:   zero for qualified cases
```

The `20%` number is an outer acceptance boundary, not a design objective.

Any material error in:

- reaction sign;
- active/inactive support state;
- lift-off/contact state;
- load direction;
- route connectivity;
- source identity;

is more serious than a small scalar magnitude deviation.

### Phase V3.13 — Escalation logic

```text

```

Examples requiring escalation may include:

- cycles/closed-loop topology outside the qualified force-method formulation;
- complex nonlinear contact networks;
- strongly nonlinear geometry;
- local shell flexibility not represented by component rules;
- high local stress assessment;
- unqualified tee/reducer/component types;
- deformation-dependent ovalization;
- nonlinear material behavior.

## 16. Evidence and anti-gaming rules

The following rules are mandatory for V3 development.

1. Freeze benchmark geometry and acceptance before observing production outputs.
2. Never loosen a threshold simply to make a benchmark pass.
3. Never add a response multiplier tied to a failing benchmark location.
4. Never infer missing engineering input from the benchmark expected result.
5. Keep software regression and engineering validation distinct.
6. Mark unexecuted validation `NOT_RUN`.
7. Do not label empty CI/status data as PASS.
8. Keep V1/V2 qualified behavior immutable while V3 is experimental.
9. Preserve exact source and semantic hashes for every governed input.
10. Require holdout route families; do not qualify only on development cases.
11. Treat contact-state/sign errors as hard failures even when magnitude error is small.
12. Keep SIF, flexibility, load, and stress-recovery authorities separate.

## 19. Summary

Empirical Calc V3 is intended to evolve the current empirical load calculation into a **physics-dominant analytical piping ROM**.

Its defining ideas are:

```text
not curve fitting
not hidden global FEA
not guessed engineering data
not SIF-as-stiffness
```

Instead:

```text
canonical geometry
+ explicit member/component mechanics
+ unit-load virtual work
+ governed B31J component flexibility
+ free-strain/load reference movement
+ restraint compatibility/contact
+ independent qualification
```

The desired end state is a fast calculation engine that is substantially more physically complete than a screening calculator, substantially lighter than a general FEA solver, and sufficiently traceable that every reaction can be followed from source authority through mechanics to published evidence.
