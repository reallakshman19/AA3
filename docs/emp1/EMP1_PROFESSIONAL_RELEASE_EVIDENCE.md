# EMP.1 professional release evidence

## Purpose

This document defines the execution boundary for Issue #1389 PR-H. It does not grant WRC method authority, bounded production authority, global EMP.1.C authority, code compliance, release authority or deployment authority.

The first bounded professional route remains:

- WRC 537 (2013);
- cylindrical host / round attachment;
- Original curves;
- gamma exactly 5;
- beta 0.05 through 0.50 inclusive;
- zero differential pressure / upstream-resolved pressure thrust;
- Kn = Kb = 1;
- WRC loads P, Vc, Vl, Mc, Ml, Mt;
- host-shell stresses at Au, Al, Bu, Bl, Cu, Cl, Du, Dl only;
- no continuous/global shell maximum claim;
- no nozzle/attachment-wall stress claim;
- no code PASS claim.

## Three distinct states

Do not collapse these states:

1. **Policy encoded** — the repository contains the required checks and fail-closed rules.
2. **Exact candidate executed** — every required command actually ran on one exact clean candidate head and passed.
3. **Deployment observed** — the exact built artifact from that candidate was deployed and independently smoke-observed.

An encoded check is not execution evidence. A `NOT_RUN` command is not PASS. A successful WRC calculation is not code compliance. A deployment receipt does not grant engineering or code authority.

## Readiness policy

Run:

```text
node scripts/emp1-professional-release-readiness-check.mjs
```

A current blocked repository is expected to return:

```text
PASS_RELEASE_POLICY_FAIL_CLOSED_CURRENTLY_BLOCKED
```

That status means the policy is truthful. It does **not** mean release prerequisites passed.

The release prerequisite gate is:

```text
node scripts/emp1-professional-release-readiness-check.mjs --require-release
```

Exit code `2` means the release is correctly blocked. The gate requires, at minimum:

- reconciled WRC source custody;
- all P0 source-semantics gates source-closed;
- direct CAUx page re-observation completed;
- genuine 01–10 evidence;
- bounded route/registry authorization from the controlled PR-E mutation;
- verified post-promotion 11/12 evidence.

The readiness checker also reasserts the immutable release envelope: cylindrical/round, Original gamma=5, beta 0.05–0.50 inclusive, zero dp, Kn=Kb=1, Au..Dl host-shell recovery, no interpolation/cross-variant fallback/off-axis authority, and no continuous/global maximum or nozzle-wall/code-compliance claim.

## Exact candidate execution

Policy-only inspection:

```text
node scripts/emp1-professional-release-candidate.mjs
```

Optional diagnostic execution, which may intentionally expose currently failing/blocking gates:

```text
node scripts/emp1-professional-release-candidate.mjs --execute-diagnostics
```

Final release execution requires a clean worktree and an immutable expected head:

```text
node scripts/emp1-professional-release-candidate.mjs \
  --release \
  --expected-head <40-char-candidate-sha> \
  --deployment-receipt <deployment-receipt.json> \
  --write-receipt validation/emp1/release/<release-candidate-receipt>.json
```

Before deployment verification, the harness executes the promotion-compatible governed chain:

```text
source custody reconciliation
P0 source semantics --require-ready
CAUx benchmark --require-direct-pdf
authorized runEmp1 bounded-route orchestration qualification
route-authority/currentness + persisted/reloaded replay falsifiers
production build
EMP.1 release-candidate Chromium journey
```

The historical `emp1-public-product-check.mjs` and the general `emp1-workbench-authority.spec.js` deliberately assert the **suspended** route in part of their coverage. They remain valuable pre-promotion regression gates but are not used as post-promotion release gates. PR-H uses `emp1-wrc-gamma5-zero-dp-orchestration-qualification.mjs` and `e2e/emp1-professional-release.spec.js` instead so a correctly authorized bounded route is not rejected merely because promotion succeeded.

Every invocation retains command identity, exit code, signal/error code, stdout SHA-256, stderr SHA-256 and byte counts. Environment/tool launch failure is `NOT_RUN_EXECUTION_ENVIRONMENT`; a nonzero exit from an actually launched command is FAIL.

## Release browser gate

`e2e/emp1-professional-release.spec.js` is intentionally post-promotion. It drives the real qualification sample through the real workbench and requires:

- A=1, B=1, prepare C=1, production C=1;
- a current/reportable C result;
- `CALCULATED=YES`, `METHOD QUALIFIED=YES`;
- `CODE COMPLIANT=NO` and `RELEASED=NO` at this engineering-candidate stage;
- an eight-point governing result only;
- no global/continuous maximum claim;
- no nozzle/attachment-wall stress claim;
- route-authority hash equality between execution and retained authority snapshot.

The browser gate verifies the promoted bounded calculation without pretending that calculation alone grants code or final release authority.

## Build artifact identity

After a successful production build, PR-H calculates one deterministic SHA-256 over all regular files in `dist/` using sorted relative paths and each file's SHA-256. Symlinks are prohibited in the release artifact.

That `buildArtifactSha256` binds the candidate receipt to the exact deployable bytes.

## Deployment receipt

Required receipt shape:


Verify independently with:

```text
node scripts/emp1-professional-deployment-receipt-check.mjs \

  --expected-artifact-sha256 <dist SHA-256>
```

The final `--release` harness runs this verifier itself. Missing deployment evidence blocks release with exit code `2`.
